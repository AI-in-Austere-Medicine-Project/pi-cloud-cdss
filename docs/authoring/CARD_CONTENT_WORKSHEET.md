# Ventilator cards — content worksheet

**Author: a credentialed clinician. Nobody else signs a card.**

Generated by `server/tools/gen_card_worksheet.py` from the card files and the engine schema, so it cannot drift from what the engine actually requires. Re-run it after every authoring pass.

**5 of 13 cards live.**

## How a card goes live

Cards deploy **one at a time**. Partial deployment is the normal state, not a migration step — an unsigned card is invisible to the pipeline and the query falls through to whatever answered it before.

1. Fill every field listed for that card below.
2. Add at least one entry to `references` — the engine refuses a card with none.
3. Set `reviewed_by` to exactly `clinician` and `review_date` to the date you signed it.
4. Set `signoff` to `true`.
5. Bump `version`.
6. `cd server && python3 -m pytest test_vent_module.py -q` — the fence tests should still pass, and that card starts carrying traffic.

The engine refuses to serve a card that is signed while any clinical field is still empty or `PENDING_CLINICAL_SIGNOFF`, so a half-filled card cannot reach a medic by accident. There is no override — `EDGECDSS_DEBUG_WARN_ONLY` does not reach this gate.

## What is NOT yours to fill

`applies_when` is dispatch vocabulary, pre-filled so the routing tests have something to assert. Review it — a wrong signal sends a real query to the wrong card — but it is not clinical content.

`id`, `title`, `version`, `source_label` are structural.
